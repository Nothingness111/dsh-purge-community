> 判定口径：`applied` = 补丁真正写入；`skipped` = 文件在但标记未命中；

## 二、0.2.1-rc.5 上为什么命中率低

npm 全局形态的目录结构与桌面版不同：

- 缺 `lib/main.js`（没有 Electron 壳），所以所有跟窗口 / host 生命周期相关的补丁无法落地
- 插件树位于 `<dsh-home>/dsh/node_modules/@deepseek-ai/...`，路径模板与桌面版不一致
- 该形态下 `skipped` 的大头是「标记存在但上下文不同」，属正常

## 五、升级 dsh 之后要做什么

1. 退出 DeepSeek Harness
2. 正常更新
3. 更新完成后 `resources/app.asar` 会重新出现 —— 此时补丁全部失效
4. 重新在插件里点「应用」，然后运行 `scripts/fix-crash-auto.cmd`
5. 用 `node scripts/check-compat.mjs` 验收，看到 `[OK] 状态: 已切换` 即可

如果新版本上出现大量 `missing_file`，说明上游又改结构了，
需要在 `lib/compat-dsh-0.2.2.mjs` 的思路上补一份新兼容层。
